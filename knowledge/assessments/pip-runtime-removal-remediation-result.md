## Baseline component inventory

The pre-remediation runtime shipped **two** copies of the affected component plus
three console entry points: the installed distribution with its metadata under
site-packages, and the wheel bundled under `ensurepip`, whose declared bundled
version matched the installed one. A bounded assertion over actual installed state
failed **12 of 12** checks, including two affected-name matches and **one
content-hash match** for the affected bundled wheel.

## Removal method

One runtime-stage-only change: transition to root, uninstall the active
distribution, remove the `ensurepip` package at the interpreter's own
`sysconfig`-derived stdlib path, remove the three console entry points, and return
to the unprivileged runtime user. **The stdlib path is derived at build time rather
than hard-coded**, so it does not carry an interpreter-version coupling; the entry
points are named explicitly and do carry one, which is recorded here rather than
hidden behind a glob.

The shared base stage is **unchanged** and still uses pip at build time. The
development stage is **unchanged** and branches from that shared base.

## Effective merged-runtime clearance

The candidate has no importable pip, no pip distribution metadata, no package

**Under Decision 0026's component-presence criterion, the established pip
Decision 0022/D shipment-hygiene blocker is cleared for this measured
`linux/amd64` runtime candidate.**

### Build-context observation, recorded and not acted on

Host-generated bytecode directories are copied into the image despite being listed
in the build-context exclusions, because those patterns are not recursive as
written. This is **pre-existing**, present in the baseline, and unrelated to this
remediation — the only change here is that the removed component's share of that
bytecode went with it. **No exclusion file was modified**, because that path was
not admitted for this slice. Recorded for separate owner disposition.

## Runtime contract regression

Every documented runtime command passes on the candidate, with deterministic
outputs **byte-identical** to the baseline: the help surface, the repository
self-check, the documented generic validation and the documented context pack. The
self-check test count rose by exactly one, which is the focused structural
invariant this slice added.

Runtime identity and security boundary are **identical**: same unprivileged user
and uid/gid, same entrypoint, command and working directory, same effective,
permitted and bounding capability sets with `CAP_SYS_ADMIN` absent, and the same
eleven privileged files.

**The image did not get smaller.** It grew marginally, because removal adds a
whiteout layer above an inherited layer that still carries the bytes. Size is not
evidence of component removal here, and must not be cited as if it were.

## Generic Python behaviour deliberately given up

In the published runtime only: the pip console command, `python -m pip`,
`python -m ensurepip`, and the default `python -m venv` bootstrap, which fails at
its ensurepip step. Documentation was re-scanned and **none of these is a
documented published-runtime contract**; every mention is host-native,
development-image, build-time or incidental. The development target retains all of
them.

## Development-target preservation

The development target builds, runs as the same unprivileged user, retains pip at
the development-lock version, retains `ensurepip`, retains all console entry points
including the audit tool, retains the lint and type-check toolchain, and passes the
canonical development-container verification route. **The cleanup did not
propagate.**

## OCI layer-history residual

still present in the **inherited interpreter layer**, including the bundled wheel

removal layer covering the three entry points, the `ensurepip` directory, the
package directory and the distribution metadata.

Recorded exactly as an **OCI LAYER-HISTORY RESIDUAL** under Decision 0026:

> The affected bytes still exist in the distributed artifact's historical layer
> set. They are **not** claimed absent. They are **not** claimed safe. Under the
> component-presence criterion Decision 0026 selected, they are **not by

No flattening was performed, none is required, and no further semantic Decision was
opened.
