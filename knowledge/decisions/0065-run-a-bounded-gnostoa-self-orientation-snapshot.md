# Run one bounded Gnostoa-self orientation snapshot

## Context

Issue #14 describes a future generic public projection capability. The reviewed
current-subject study found a smaller first consumer need: an arriving Gnostoa
maintainer or agent lacks one compact, source-bound answer to “what now?” The
task-envelope projector covers one task and the context pack traverses an OKF
graph; neither represents portfolio source freshness, conflicting selection,
implemented-versus-proposed capability or the route back to adoption.

The owner selected D14-O1 from integrated `main`
`1acf9bb448e7342bbf1b8a4cf16f3b2a86225f89`. This Decision records construction
authority. It does not authorize merge or promote the experiment to adopters.

## Decision

1. Construct one `normative`, experimental Gnostoa-self snapshot and projector
   under `tasks/`, with focused tests and a self-knowledge result. Route the
   compact view from `README.md`, `docs/roadmap.md` and `AGENTS.md`. Keep the
   implementation outside the public inheritance and runtime surface.
2. Use one closed internal JSON format to produce normalized machine JSON and
   Markdown from the same facts. Bind facts to concise source records carrying
   identity, observation time, coverage and explicit uncertainty.
3. Recompute local-file digests and compare any separately supplied caller
   observations. A declared hash records what the producer observed; it does not
   authenticate provider truth. Invalid or future observation times cannot
   establish freshness.
4. Foreground purpose, implemented and proposed capabilities, the selected
   current item or none, one next action, proposed successor and admission state,
   material blockers, constraints and return-to-adoption. Missing, partial,
   stale or conflicting input cannot yield `CURRENT`; multiple selected items
   remain visible and are never resolved by issue number or labels.
5. Cap emitted Markdown at 5,000 Unicode code points, including metadata and
   links. `OVER_BUDGET` reports measured and allowed size without truncating a
   blocker or silently increasing the limit. Measure the provisional five-minute
   reader target separately.
6. Reuse task-envelope canonical serialization, explicit-observation, escaping
   and budget patterns. Leave its public schema and command unchanged. Leave
   context-pack unchanged because its graph and token-budget contract does not
   cover this slice.
7. Read only local inputs and emit to stdout or a caller-selected local file. Add
   no provider SDK, write-back, public schema or command, package entry point,
   runtime, service, graph, scheduler or model dependency.
8. Treat a negative or disproportionate result as valid. Simplify, remove or
   revisit the route if it is not consumed, cannot preserve critical facts within
   budget or costs more upkeep than it saves.

## Consequences

This slice does not satisfy or weaken Issue #14's future generic promotion
criteria. It establishes neither adopter utility, L10 closure, automatic roadmap
maintenance, semantic completeness nor acceptance enforcement. Provider facts
remain provider facts, human semantic decisions remain human, and every current
claim retains its observation boundary.

Inputs contain concise public project facts and references, without credentials,
raw prompts, hidden reasoning or copied provider bodies. Existing consumers,
public schemas, CLI, package, runtime and public-surface digest remain unchanged.

Verification starts with an explicitly constructed false-current baseline, then
tests deterministic source binding, freshness, conflicts, mandatory-fact
coverage, machine/Markdown equivalence, the 5,000-code-point boundary and actual
entry routing. Container policy, fast, regression, smoke and extended suites bind
the final candidate. Missing implementation is recorded as `UNMET`, not called a
behavioral failure.
