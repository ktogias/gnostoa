# Project knowledge router

Keep this file short. Route to one source; do not duplicate the guidance here.

- New project: read `.knowledge-kit/guidance/workflows/bootstrap-new-project.md`.
- Existing project adoption: read
  `.knowledge-kit/guidance/workflows/adopt-existing-project.md`.
- New profile layer: read
  `.knowledge-kit/guidance/workflows/create-specialization.md`.
- Routine knowledge change: read
  `.knowledge-kit/guidance/workflows/daily-change-loop.md`.
- Any repository change: read `.knowledge-kit/guidance/workflows/propose-review-merge-change.md`.
- Resume or handoff: read `.knowledge-kit/guidance/workflows/resume-and-handoff-change.md`.
- For implementation and verification: read
  `.knowledge-kit/guidance/workflows/develop-verification-first.md`.
- CI or hook work: read
  `.knowledge-kit/guidance/workflows/configure-continuous-integration.md`.
- Before changing normative knowledge: read
  `.knowledge-kit/guidance/guardrails/non-negotiable.md`.

Validate the change policy, project profile and bundle before completing a
change. Load only the selected route and the concepts reached from the task. Do not load
or copy `.knowledge-kit/knowledge/`; that directory is toolkit-maintainer
self-knowledge and is outside this project's inheritance boundary.
